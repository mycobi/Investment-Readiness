# Glossary and conventions

**Status:** Proposed public terminology for RFC review.

| Term | Meaning in this specification |
| --- | --- |
| IRD | Investment Readiness Diagnostic: the assessment of company preparation for institutional diligence. |
| IRS | Investment Readiness Score: the 0-1000 summary produced by the diagnostic. It is not a funding entitlement. |
| Investment readiness | Preparation to make the company's condition and material risks assessable through supporting information for institutional capital diligence. It is not a funding entitlement. |
| Dimension | One of five assessment domains, each with a maximum of 200 points. |
| Criterion | One of 25 named areas within the five dimensions. A criterion is not necessarily one product question. |
| Claim | A statement about a company's condition offered for assessment. |
| Evidence | Material that supports, qualifies or contradicts a claim. |
| Provenance | The origin and handling of evidence, including its source and relevant dates. |
| Corroboration | Comparison with additional records or sources to assess support for a claim. |
| Connected system | A source accessed through an authorized integration. Connection alone does not establish independence or accuracy. |
| Evidence confidence | An interpretation of support for a claim, distinct from the claim itself. Public numeric confidence rules are not specified. |
| Band | A range used to summarize assessed investment readiness. Band names are pending review. |
| Stage-relative | Interpretation considers a company's declared stage and applicable expectations. It does not assign funding eligibility. |
| TRL | Technology Readiness Level: a nine-level technology maturity scale that originated at NASA, cited in the criteria index as a precedent for a published shared vocabulary. Not part of the IRS. |
| FH / OM / MP / GC / TR | Financial Health / Operational Maturity / Market Position / Governance and Compliance / Traction. |
| RFC | Request for Comments: a documented proposal or review process. |
| CLA | Contributor License Agreement: permission for project use of contributed material. |
| PR | Pull request: proposed repository changes submitted for review. |
| Normative | A requirement of this public specification. |
| Informative | Explanation, example or guidance that is not itself a requirement. |
| MRR / ARR | Monthly recurring revenue / annual recurring revenue. |
| CAC / LTV | Customer acquisition cost / customer lifetime value. |
| ICP | Ideal customer profile. |
| TAM | Total addressable market. |
| GTM | Go-to-market. |
| IP | Intellectual property. |
| KPI | Key performance indicator. |
| QA | Quality assurance. |
| SLA | Service-level agreement; in review governance, a stated acknowledgment target. |
| NRR / GRR | Net revenue retention / gross revenue retention. |
| CRM | Customer relationship management. |
| CPA | Certified public accountant. |
| P&L | Profit and loss statement. |
| CI | Continuous integration: automated checks on proposed changes. |

## Normative language

The key words MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, NOT RECOMMENDED, MAY, and OPTIONAL are interpreted as described in BCP 14 (RFC 2119 and RFC 8174) only when they appear in all capitals. BCP means Best Current Practice.

Use these words only for requirements, not to turn explanatory prose into obligations. This convention does not assert affiliation with a standards organization.
